<div class="aldc-source-setup" data-aldc-source><h2>Prepara el código de 4.3.0</h2><p>Para Claude Code, Copilot CLI y Codex: Git, Node.js 20+ y el host instalado y autenticado. Usa un proyecto AL separado, con app.json. Ejecuta estos comandos PowerShell desde una carpeta de herramientas fuera del proyecto, una sola vez. Usa una carpeta ALDC-4.3.0 nueva; no sobrescribas un clon existente.</p><div class="aldc-command"><button type="button" data-aldc-copy hidden>Copiar</button><pre><code>git clone https://github.com/javiarmesto/ALDC-AL-Development-Collection.git ALDC-4.3.0
if ($LASTEXITCODE -ne 0) { throw &quot;Clone failed&quot; }
git -C .\ALDC-4.3.0 checkout v4.3.0
if ($LASTEXITCODE -ne 0) { throw &quot;Checkout failed&quot; }
$aldc = (Resolve-Path .\ALDC-4.3.0).Path
$project = (Resolve-Path &#x27;C:\Path\To\YourALProject&#x27;).Path</code></pre></div><p>Sustituye la ruta de ejemplo antes de ejecutar. Mantén abierta esta sesión PowerShell: los siguientes comandos usan $aldc y $project. El checkout queda separado de una rama deliberadamente.</p><a href="https://github.com/javiarmesto/ALDC-AL-Development-Collection/tree/v4.3.0">Consultar el código de 4.3.0 · v4.3.0</a></div>

<section class="aldc-first-task"><div class="aldc-start__eyebrow">02 / TU PRIMERA PETICIÓN</div><h2>Empieza con una decisión de diseño.</h2><p>En el host elegido, pide al Architect de ALDC que trabaje sobre un requisito acotado. Comprueba primero qué instrucciones están disponibles.</p><div class="aldc-command"><button type="button" data-aldc-copy hidden>Copiar</button><pre><code>Usa el rol Architect de ALDC. Identifica las instrucciones y skills de ALDC que realmente has cargado, o indica qué falta.

Requisito: añadir una nota de entrega a los clientes para que el usuario pueda consultarla en la ficha del cliente.

Lee la versión objetivo en app.json. Evalúa el alcance y propone las especificaciones necesarias y sus dependencias. No generes AL, no compiles, no despliegues ni cambies configuración. Detente para mi revisión.</code></pre></div></section>
<div class="aldc-install-footnotes"><h2>Qué no hace la instalación</h2><p>Los perfiles BC28 / BC29 orientan a ALDC; no instalan la extensión AL, el compilador, los símbolos ni un entorno de Business Central. Los hosts de terminal usan sus herramientas disponibles; las herramientas de VS Code no se trasladan por nombre. Configura cada proyecto según su destino.</p><p>BCQuality es opcional y se instala por separado. Doctor requiere Python 3.9+ y separa configuración y observaciones por operación. Instalar archivos no equivale a superar una revisión ni una compilación.</p><div class="aldc-guide-links"><a href="../plugin-packaging/">Actualización y recuperación</a><a href="../native-bc29/">BC28 / BC29</a><a href="../bcquality/">BCQuality</a><a href="../getting-started/">Flujo de desarrollo</a></div></div><p class="aldc-copy-status" role="status" aria-live="polite" data-aldc-copy-status></p></div>
